# Add the owner and keep the assistant on the call

For customer support, set `owner_join: "when_live_agent"`. The assistant navigates menus, waits for a live representative, explains the supplied case and rings the configured owner. The owner hears the recording disclosure and presses 1 to join. The assistant remains to help both people until the actual objective is resolved. A recorded queue announcement does not qualify as a live representative.

Use `owner_join: "when_needed"` to ring the owner only if the conversation requires their participation. Omit the field or set `"disabled"` for ordinary calls. Enabling either mode authorizes one additional telephone call to the configured `selfNumber`. It does not authorize another destination, a retry after an uncertain outcome, payment or a commitment beyond the supplied task limits. Self calls and reminders cannot use this mode.

The owner has 10 seconds to press 1 after answering. No input or another digit hangs up the invitation without joining it to the conference. Busy and unanswered invitations leave the assistant and business connected. The service makes at most one owner invitation per task, including after restarts and concurrent tool requests. If dispatch is uncertain, inspect that task instead of starting again.

The support duration default remains 900 seconds, including time on hold. Set a longer `max_duration_seconds` when authorizing a longer wait. The business and owner each have a 60-second ringing timeout. Cancellation and the duration watchdog terminate every attempted leg. The assistant leaving ends the conference; a business disconnect is cleaned up at the next provider observation, normally within 15 seconds. Provider outages can delay termination.

## How the three participants connect

The service first creates an internal participant that targets a private TwiML App. Its signed webhook registers the existing ElevenLabs agent and returns the provider's connection TwiML unchanged. Once that registration completes and the assistant's call is connected, the service dials the business into the same conference. This startup order avoids dialing an instant-answer menu before the assistant connection is prepared. The assistant keeps its own audio connection throughout the conference. Its ordinary in-band keypad tones can reach the business through that audio connection.

The agent's `connect_owner` webhook can add only the stored owner number. A random token binds this tool to one active task; ElevenLabs receives it in a secret dynamic header variable. The tool cannot choose a telephone destination. The owner receives a separate call that asks for acceptance before joining the same conference. The existing business and assistant participants remain in place.

The service stores each participant's identity before accepting observations. It persists each dialing intent before making a request, and it never repeats an unresolved dialing attempt. Signed status callbacks can recover identities after a lost response. The business call ID and assistant conversation call ID remain separate. Every provider observation checks the expected account and destination.

The public result exposes owner acceptance and each leg's status without the tool token or the assistant's connection URL. Acceptance proves that the owner pressed 1; it does not prove that audio was heard. Participant call prices exclude additional Twilio conference charges, so no total conference price is claimed. All three participants may be billed simultaneously while connected. ElevenLabs recording includes the audio that reaches the assistant, including the owner after joining.

This implementation follows [Twilio's documented AI conference pattern](https://www.twilio.com/en-us/blog/developers/tutorials/product/connect-twiml-app-twilio-conference), the [conference participant API](https://www.twilio.com/docs/voice/api/conference-participant-resource), [ElevenLabs call registration](https://elevenlabs.io/docs/eleven-agents/phone-numbers/twilio-integration/register-call), and its [in-band keypad tool](https://elevenlabs.io/docs/eleven-agents/customization/tools/system-tools/play-keypad-touch-tone). ElevenLabs' built-in transfer is not used because it removes the assistant.

## Configure an existing installation

Resource changes and deployment require user authorization and a fresh review. The following helper can prepare the exact plan before that decision. It never places a call or deploys a Worker.

1. In the implementation checkout, securely provide the existing `private/service-config.json`, `private/worker-secrets.json`, `private/setup.json` and provider credentials. The deployment helper uses `private/setup.json` to select the existing Cloudflare account. Keep these files ignored and mode 600. Do not copy another checkout's unfinished private state without establishing ownership. Coordinate with any agent updating the same live installation before preparing or applying a plan.
2. If prompt-text overrides have not already been enabled, first review, apply and read back the permission-only agent update described in [the deployment procedure](DEPLOYMENT.md). Then build, review and deploy this Worker source with the existing configuration. Read back the deployed version. This compatible Worker supplies `owner_join: "disabled"`, silent task rules and an unusable disabled tool header on ordinary calls, before the saved agent starts referencing these variables. It also supports exact-message reminder overrides. Conference calls remain unavailable until the App SID is configured.
3. Run `npm run conference:setup -- prepare`. This reads the selected Twilio account, ElevenLabs user/workspace and saved agent, then writes `private/conference-setup/plan.json` and private raw responses. Inspect at least one complete response from each provider before relying on its parsed identity. Review the exact old/new prompt, preserved saved settings and resource requests with a fresh adversarial reviewer, and obtain resource change authorization. The reviewer must verify the compatible Worker deployment before saving `{ "verdict": "ship", "planSha256": "<exact reviewed hash>", "compatibleWorkerDeployed": true }` in `private/conference-setup/review.json`. Apply rejects a review lacking that prerequisite.
4. Run `npm run conference:setup -- apply` once. It creates the private TwiML App and owner connection tool, replaces the managed prompt, merges the new tool ID and sets input/output audio to `ulaw_8000`. It preserves the saved model, voice, existing tools, knowledge, first message, other conversation settings and platform settings. It writes the returned App SID as `twilioApplicationSid` into local configuration and the Worker configuration secret.
5. Build, review and deploy again with the resulting App SID configuration to enable conference calls. No call-start drift or fingerprint gate is added. The existing `/webhooks/twilio/inbound` Access bypass must accept query strings on that same path; it must not expose management or recording routes. Unknown inbound telephone calls remain rejected.
6. Read back the App's account, private application-connect setting, exact callback URL and method; the tool's secret header and bound call ID; and the saved agent's prompt, tool ID and audio formats. Verify callbacks and owner authentication before requesting a separately authorized real call.

An exclusive execution lock and persisted mutation intents prevent duplicate setup. If a setup process dies, inspect its recorded PID, journal and raw evidence before removing its own stale lock. An `intent` entry means the outcome is unknown. Reconcile it against the exact provider resource before recording a completed response. Never reset the journal or rerun creation to find out what happened. Source, configuration or saved-agent changes after review invalidate the plan. A concurrent manual edit during the saved-agent PATCH cannot be protected by a provider compare-and-swap API, so coordinate that update with the owner.

Later `agent:plan`, `agent:apply` and `agent:readback` maintenance preserves all installed webhook tool IDs. Conference setup owns the owner tool's creation and attachment. Review its configuration through the separate conference readbacks; a general prompt update does not validate or recreate that resource.

ElevenLabs rejects an update containing both deprecated inline `tools` and `tool_ids`. Setup omits the deprecated field only when every entry exactly matches a saved `built_in_tools` definition. If a legacy tool lacks that representation, preparation fails before resource creation so its migration can be reviewed separately. Existing referenced tool IDs remain preserved.

If the provider explicitly rejects an agent update and a fresh readback proves the saved agent is unchanged, archive the original plan, journal, approval and raw rejection. A separately reviewed replacement plan may reuse the confirmed App and tool IDs and send one corrected agent update. Preserve the rejected attempt in the recovery evidence. Do not repeat creation requests or treat an uncertain outcome as a confirmed rejection.

To roll back, first stop new conference calls and confirm existing conferences have ended. A separately reviewed rollback can restore the saved conversation configuration and prior local configuration from the plan. Preserve the Durable Object namespace and existing call history. Do not delete an App or tool used by another deployment or by an active call.

## Verification limits

Local tests use synthetic provider responses. They exercise real Worker routes, signed callbacks, scoped tool authorization, raw connection TwiML, owner acceptance, restart recovery, participant identities, pricing labels and all-leg cancellation. They do not establish live telephone audio, menu-tone recognition through the conference, human-versus-recording judgments, or provider behavior for an actual TwiML App call. Provider setup, deployment and an explicitly authorized telephone acceptance test remain required before claiming the feature works in production.
