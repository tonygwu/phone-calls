# How the phone-calling service works

Historical architecture snapshot: this model predates the user-authorized simplification on 2026-10-28. Its readiness, budget, fingerprint and duplicate-admission components no longer describe the current implementation. See ../docs/OPERATIONS.md for the current call path. The generated views remain a record of the earlier design.

An owner asks a client to make one call with a purpose, facts and explicit limits. The Worker authenticates that owner, and a durable coordinator stores the task and reserves its allowance before contacting ElevenLabs. The conversational agent receives fresh context for that call. The client can disconnect and later retrieve separate telephone status, task outcome and evidence.

This report describes the deployed private service. Authenticated readiness and provider readbacks establish its Cloudflare Access application, dedicated Twilio number and ElevenLabs agent. Codex, ChatGPT and the primary Claude Code profile have connected. Three additional Claude profiles are registered and await individual login. GPT-4.1 Mini appears in the real-call billing evidence and generated simulation turns; that evidence does not guarantee future responses.

The corrected prompt is deployed with ordinary US destinations enabled. Exact provider configuration and Worker version readbacks passed; the runtime continues to require owner authorization and current budget/credit checks before every call. ElevenLabs separately uses Gemini 2.5 Flash for post-call analysis.

Start with [the generated view guide](views/README.md). It links the overall call journey, the persistent recovery path, the agent's permissions and adjacent data cards. The canonical [model](model.jsonl) cites implementation sources; the diagrams are generated from it. The source root is this repository. Other MCP services, provider internals and the user's unrelated account resources are outside scope.

New requests first await seven concurrent provider admission reads for configuration, routing, credits, rates and funding. Once those checks and the budget pass, the service persists a pending task and alarm and returns its call ID. The alarm later writes a dispatch marker before sending a single outbound initiation request. Identical existing requests return the unexpired stored result without repeating admission checks.

An ambiguous dispatch leaves the call unresolved and blocks another call. The durable alarm prioritizes active calls, reads provider state, requests termination when required, and verifies it. Termination requests can repeat until the provider confirms hangup; dialing never repeats. The saved ElevenLabs agent also receives a per-conversation duration limit. Callback data triggers an authoritative read, and durable observation sequence numbers prevent a delayed older read from replacing a newer result or reducing budget accounting.

Provider analysis that a reminder was spoken does not prove mailbox receipt. The owner confirmed the first real voicemail arrived completely and once. Eleven text simulations produced six accepted examples and five preserved failures across prompt revisions. Corrected examples cover bookings, support, authority boundaries and a live-person reminder. Text simulation could not execute real keypad tones, and production booking/support outcome extraction remains unverified. These are bounded examples, not a reliability estimate. The non-Twilio cost allowance also requires current operator verification; an expired quote blocks new calls instead of silently treating unknown costs as zero.

Private content expires after 30 days. Minimal request hashes prevent ancient retry IDs from placing a second call, and aggregate budget totals remain without call contents. An unresolved call at expiry leaves a content-free safety block after its brief and transcript are removed.
